# 快乐8固定规则研究台 · HappyEight

当前网页与 HTTP 后台仅启用《快乐8_杀号优化_100期复核.xlsx》对应的固定评分模型：上上期号码 ±1 生成20个候选，冻结模型评分后保留10–14个。版本 `shift20-rf-1.0.0`，规则、模型来源与复核方法见 [docs/LOCKED_RULE.md](docs/LOCKED_RULE.md)。个人非商业研究项目。

项目早期整合的四个上游代码快照保留在 `vendor/`，版本记录见 [UPSTREAM_SOURCES.json](UPSTREAM_SOURCES.json)。旧融合引擎和独立图形引擎仅供离线审计，不再通过网页或预测 API 生成号码。旧预测记录原样保留，放入归档查看。

## 已实现

- 固定下一期预测：默认先增量同步最近开奖，使用最近12期构造特征，上上期 ±1 生成20个候选；固定评分排序和数量策略，不提供模型、窗口或数量切换。
- 可追溯记录：保存目标期、数据截止期、上上期来源、20个候选、保留/删除号码、评分、输入指纹和模型指纹；开奖导入后自动核对。
- 统一数据：SQLite、CSV/JSON导入导出、每期20个不重复号码校验、去重、冲突整批回滚、来源记录。
- 在线同步：优先复用 gin-18 的汇鸟接口（自动分页），中彩网作为备用；增加超时、重试和数据校验，不可用时明确报错。
- 固定规则回测：逐期只输入目标期之前12期，最多复核300期，且只复核模型训练截止2026178之后的期数。2026179–2026278与选定表格逐期完全一致：100期保留1400个、命中374个，最低1个、最高8个，18期不足3个。
- 页面仅保留下一期预测、规则回测、开奖数据、预测与复盘；独立图形 API 返回410，旧预测归档不重算。

## 早期四项目融合（离线保留）

| 上游 | 直接调用的模块 | 在融合版中的职责 |
|---|---|---|
| [KittenCN/kl8-lottery-analyzer](https://github.com/KittenCN/kl8-lottery-analyzer) | `compute_enhanced_scores` | 近期动量、共现谱与Dirichlet平滑特征 |

其中 gin-18 是统计/工具项目，本身不提供预测器。融合版没有把它虚构为“第四个AI模型”。三个分析分支归一化后固定等权，分数只用于排序，不是中奖概率。

## 本机启动

需要 **Python 3.11–3.13 和 Node.js 24**。无须 API Key、云服务器或 Supabase。

```bash
python -m venv .venv
# Windows 激活：.venv\Scripts\activate
# macOS/Linux 激活：source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

打开 **http://127.0.0.1:8768**。Windows 安装好 Python 和 Node.js 后，也可双击 `start.bat`。

默认仅监听本机。`--port` 可改端口，`--database` 可改数据库路径，`--no-seed` 可跳过内置数据。`KL8_NODE` 可指定 Node.js 路径。

## 云端个人试用

仓库包含 Dockerfile 与 Railway 配置，可部署完整 Python/Node 分析引擎。设置 `KL8_ACCESS_PASSWORD`（至少16字符），用户名默认为 `happy8`，可用 `KL8_ACCESS_USERNAME` 修改。只通过 HTTPS 访问，浏览器会提示输入账号密码。密码存于部署环境变量，不能提交到仓库。

容器默认开启 `KL8_REQUIRE_AUTH=1`，未配置足够长度的密码会拒绝启动。所有页面、静态资源和数据接口均受认证保护，仅 `/api/health` 返回不含数据的健康状态。未设置密码的本机启动方式保持不变。

挂载持久化卷至 `/data`，数据库位于 `/data/fusion.sqlite`，重启和更新后保留导入数据及锁定记录。此版本用于单人试用，不提供多个用户的数据隔离。建议单实例、1GB内存；空闲时可在 Railway 开启休眠。

## 数据与验证边界

“下一期预测”调用冻结的 `RF_5_80` 模型，不在线训练或重新搜索规则。累计评分目标4仅是确定保留数量的参数，不表示保证命中4个。历史100期曾参与研究，属于复核，不是独立前瞻验证。默认自动更新最近一页数据；若更新失败会明确提示。数据超过1天未更新时禁止自动判定实时下一期，可手动填写紧邻的目标期号进行历史研究。跨年编号不会简单加一，需要手动核对。所有自动推算期号均不表示已验证官方开奖日历。

生成的预测自动存入原有 `experiments` 表，页面展示的号码与保存内容来自同一次计算；更新目标期开奖结果后，在「预测与复盘」查看实测命中。既有记录与数据库保持兼容，旧版本记录默认归档，不删除、不改写。

首次启动导入并合并 **2,097期历史快照，2020001至2026276，截止2026-10-17**：Luck8 自带的1,545期旧数据，加上 `samples/history-snapshot.json` 中从汇鸟接口取得的近1,000期数据，按期号去重。近1,000期号码已与500走势图逐期交叉核对一致；这不等于逐期官方认证。页面明确展示截止日期和数据来源。可以在线同步或导入新的CSV/JSON。

CSV支持 `issue,date,numbers` 或 `期号,开奖日期,开奖号码`。号码列用双引号包住以逗号分隔的20个号码。导出的JSON可再次导入。

“锁定”表示相对于**当前库内**尚未导入的期号冻结分析，不能证明提交早于真实开奖时间。正式前瞻验证前必须先更新数据，并在真实开奖前锁定。数据库是本机文件，可被机主修改，不是第三方公证系统。

奖金规则沿用 gin-18 快照，**未核验当前官方版本**，仅用于规则演示。未根据原项目的“推荐”“置信度”文案声称预测有效。

## 修正和隔离

1. LuckyDD 原推荐接口给评分增加随机数，融合版不调用该接口，也不把评分显示成准确率。
2. LuckyDD 原遗漏计数存在最新命中为1、从未出现为0的问题，适配层统一为0和窗口长度。
3. Luck8 原期望值函数拿同一期号码子集和自身计算命中，存在目标泄露；该函数与旧奖金表不参与融合。
4. KittenCN 外部图嵌入缓存可能包含窗口外数据，默认禁用；PCA、遗传算法、Copula、FP-Growth完整候选生成链仍保存在上游源码中，本版没有声称已接入所有实验功能。
5. 移除 Luck8 抓取脚本中的上游硬编码会话Cookie，融合采集器不依赖私人登录信息。

## 历史版本 v0.3：上一期重号偏重修正

Luck8 原来的 `1/(相隔天数+1)` 权重会过度放大最近一期。本适配层改为调用其 `analyze_frequency(weight_recent=False)`：所选窗口内每期权重相同，不人为排除任何上期号码。其余两个分支及固定三等权融合保持同一方法，没有根据测试期命中结果搜索参数。

候选展示新增已知上期的开奖对照、逐组重合数和模型版本；回测同时展示与上一期平均重合数、对下一期实际平均命中数。两者含义不同。部分参数下候选仍可能全部来自上一期，不能把“减少重号”当作有效预测的证据。

旧预测保存原号码和原模型版本，不会随新模型重新计算。修正前后对照记录见 `docs/recency-audit.json`。

## 历史版本 v0.4：几何走势图独立实验（网页入口已停用）

旧版本曾提供「走势图 · 图形补点」、历史回放和图形预测锁定。当前只保留离线代码、测试及历史文档，不提供这些网页入口；它们不参与当前固定模型的预测调度。

几何模块版本为 `geometry-0.1.0`。原有统计融合引擎仍为 `0.3.0`，不因新增图形界面而改变其评分权重。图形评分与旧融合策略独立显示和验证。

首次固定规则500期历史回测（2025130–2026278，每期选10）：图形等权平均命中2.526；正方形2.510；长方形2.488；菱形2.446；同数量随机对照2.506；理论随机均值2.500。该小差距不构成稳定优势证据。详见 [docs/geometry-audit.json](docs/geometry-audit.json)。
